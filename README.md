# Local Claude Code

Терминальный ИИ-ассистент для работы с кодовой базой. Внутри 4 агента: Architect, Coder, Reviewer, Executor.
Работает из коробки на **Windows** (PowerShell, cmd, Windows Terminal) и **Android (Termux)**, а также на Linux и macOS.

- **Ноль зависимостей.** Нужен только Node.js ≥ 18.17. В `node_modules` пусто, на телефоне ничего не компилируется, `npm install` не может сломаться.
- **Потоковый вывод.** Клиент Anthropic Messages API (SSE) написан на встроенном `fetch`, повторы при 429/5xx/529 делаются автоматически.
- **Кроссплатформенные инструменты.** Поиск, glob и правки сделаны на чистом JS, поэтому не нужны `grep`/`rg`/`find`. Пути принимаются как через `/`, так и через `\`, а в CRLF-файлах сохраняются окончания строк.

## 1. Установка

### Windows

1. Поставьте Node.js LTS с https://nodejs.org или командой `winget install OpenJS.NodeJS.LTS`. После установки откройте **новое** окно терминала.
2. Распакуйте архив, например в `C:\tools\lcc`, и запустите:
   ```bat
   cd C:\tools\lcc
   setup.bat
   ```
   Скрипт проверит Node, выполнит `npm install -g .` (это работает офлайн, зависимостей нет) и создаст `%USERPROFILE%\.lcc\.env`.
3. Запустите в папке своего проекта:
   ```powershell
   cd C:\work\my-project
   lcc
   ```

Если `npm install -g` недоступен (например, из-за корпоративных политик), можно запускать напрямую: `node C:\tools\lcc\bin\lcc.js`.

> `npm install -g .` создаёт ссылку на папку с программой, поэтому не удаляйте и не переносите её после установки.

### Android (Termux)

Termux ставьте из **F-Droid** или с GitHub Releases: версия в Google Play устарела и не получает обновления пакетов.

```bash
pkg update && pkg install -y nodejs-lts git
# скопируйте архив в Termux и распакуйте, например:
#   termux-setup-storage
#   cp ~/storage/downloads/local-claude-code.zip ~ && cd ~ && unzip local-claude-code.zip
cd ~/local-claude-code
bash install-termux.sh
```

Затем:
```bash
cd ~/my-project      # проекты держите в ~, а не в ~/storage/shared
lcc
```

Без установки можно запускать так: `node ~/local-claude-code/bin/lcc.js`.

### Linux / macOS

```bash
cd local-claude-code && npm install -g . && lcc
```

## 2. Ключ API

Ключ ищется в таком порядке:
1. переменные окружения `ANTHROPIC_API_KEY` или `ANTHROPIC_AUTH_TOKEN`;
2. файл `.env` в папке проекта;
3. файл `~/.lcc/.env` (на Windows это `%USERPROFILE%\.lcc\.env`).

Если ключ нигде не найден, при первом запуске программа спросит его (ввод скрыт), а также эндпоинт и модель, и сохранит всё в `~/.lcc/.env` с правами 600.

Кастомный эндпоинт (прокси или шлюз, совместимый с Anthropic Messages API):
```
ANTHROPIC_BASE_URL=https://my-gateway.example.com
ANTHROPIC_AUTH_TOKEN=...      # если шлюз ждёт Bearer вместо x-api-key
```
Остальные параметры описаны в `.env.example`.

> Если доступ в интернет идёт через HTTP-прокси: в новых версиях Node (24+) задайте `NODE_USE_ENV_PROXY=1` вместе с `HTTPS_PROXY=...`. В старых версиях встроенный `fetch` системный прокси не использует, поэтому проще указать прокси-шлюз в `ANTHROPIC_BASE_URL`.

## 3. Как пользоваться

```
[auto] → добавь в api/users.py эндпоинт удаления пользователя и тесты к нему
```

### Режимы (`/mode`)

| режим  | что происходит |
|--------|----------------|
| `auto` | **Architect** изучает проект и составляет план → **Coder** пишет код → **Reviewer** проверяет его (при замечаниях задача возвращается к Coder) → **Executor** запускает тесты и сборку (если они падают, задача снова уходит к Coder) → итог |
| `plan` | то же самое, но сначала показывается план и спрашивается подтверждение |
| `solo` | один агент со всеми инструментами и памятью диалога. Быстрее и дешевле, подходит для вопросов и мелких правок |

Если запрос является вопросом («как устроена авторизация?»), Architect отвечает сам, без запуска конвейера.

### Команды

| команда | действие |
|---------|----------|
| `/mode auto\|plan\|solo` | сменить режим |
| `/yes` | включить или выключить автоподтверждение записи и команд |
| `/model <имя>` | сменить модель для всех агентов |
| `/clear` | очистить память агентов |
| `/cost` | показать расход токенов |
| `/status` | показать ОС, оболочку и настройки |
| `!<команда>` | выполнить команду в оболочке напрямую, без ИИ |
| `/exit`, Ctrl+D, Ctrl+C ×2 | выход |

Ctrl+C во время работы прерывает текущую задачу, а запущенная команда завершается вместе с дочерними процессами.
Строка, оканчивающаяся на `\`, продолжается на следующей. Многострочный текст можно просто вставить.

### Однократный запуск

```bash
lcc -p "найди и исправь падающий тест"            # конвейер auto
lcc -m solo -p "объясни, что делает src/main.py"
lcc -y -p "обнови зависимости и прогони тесты"     # без подтверждений
```

### Подтверждения и безопасность

- `write_file`, `edit_file` и `run_command` перед выполнением показывают diff или команду и ждут ответа: **y**, **n** или **a** (разрешать этот инструмент до конца сессии).
- Опасные команды (`rm -rf /`, `format C:`, `git push --force`, `mkfs`, `shutdown` и т.п.) **всегда** требуют ручного подтверждения, даже при `/yes`.
- Запись вне папки проекта запрещена. Разрешить её можно через `LCC_ALLOW_OUTSIDE=1`.
- Команды выполняются без stdin, поэтому интерактивные программы не зависают. Есть таймаут (`LCC_CMD_TIMEOUT`).

### Инструкции проекта

Положите в корень проекта `LCC.md` (или `CLAUDE.md` / `AGENTS.md`) с описанием стека, команд тестов и правил. Этот файл получат все агенты. Пример лежит в `LCC.example.md`.

## 4. Архитектура

```
local-claude-code/
├── bin/lcc.js                 точка входа (проверка версии Node)
├── src/
│   ├── index.js               разбор аргументов CLI, запуск REPL или -p
│   ├── config.js              .env, переменные окружения, запрос ключа при первом запуске
│   ├── platform.js            определение ОС (Windows/Termux/Linux/macOS), выбор оболочки
│   ├── usage.js               учёт токенов
│   ├── api/anthropic.js       потоковый клиент Messages API: SSE, tool_use, повторы
│   ├── agents/
│   │   ├── prompts.js         системные промты 4 агентов и соло-режима
│   │   ├── agent.js           цикл модель → инструменты → модель, сжатие контекста
│   │   └── orchestrator.js    конвейер с циклами исправлений
│   ├── tools/
│   │   ├── index.js           реестр, наборы прав агентов, подтверждения
│   │   ├── files.js           read_file, write_file, edit_file, list_dir
│   │   ├── search.js          glob, grep (на чистом JS)
│   │   ├── command.js         run_command: PowerShell/cmd или bash, kill дерева процессов
│   │   └── fsutil.js          пути, обход с .gitignore, glob → RegExp
│   └── ui/
│       ├── term.js            цвета, Unicode/ASCII, ширина символов, спиннер
│       ├── renderer.js        вывод агентов, diff, подтверждения
│       └── repl.js            ввод, история, slash-команды, Ctrl+C
├── test/                      unit-тесты и сквозной тест на мок-сервере API
├── setup.bat                  установка на Windows
├── install-termux.sh          установка в Termux
└── .env.example
```

**Права агентов**

| агент | инструменты |
|-------|-------------|
| Architect | read_file, list_dir, glob, grep (только чтение) |
| Coder | все инструменты |
| Reviewer | только чтение |
| Executor | чтение и run_command |

**Как выбирается оболочка**

| ОС | оболочка |
|----|----------|
| Windows | `pwsh` (PowerShell 7), если он установлен, иначе `powershell.exe` 5.1. Команда передаётся через `-EncodedCommand`, так что кавычки не ломаются, а вывод идёт в UTF-8. Выбрать вручную можно через `LCC_SHELL=cmd\|powershell\|pwsh` |
| Termux | `$PREFIX/bin/bash`. Агенты знают, что в Termux нет root и `/tmp` и что пакеты ставятся через `pkg` |
| Linux/macOS | `bash`, если его нет — `sh` |

**Терминал.** В Windows Terminal, VS Code, Termux и POSIX-терминалах используются Unicode-символы. В старом conhost и при `LCC_ASCII=1` включается ASCII. Цвета отключаются при `NO_COLOR` и при выводе в файл. Длинные строки обрезаются по ширине окна, CJK и emoji считаются символами двойной ширины, поэтому строки не съезжают.

## 5. Тесты

```bash
npm test
```
Набор включает 17 тестов: файловые инструменты, CRLF, glob/grep, команды и таймауты, разбор `.env` и аргументов, а также сквозной прогон конвейера (Architect → Coder → Reviewer «ИСПРАВИТЬ» → Coder → Reviewer «OK» → Executor «PASS») на локальном мок-сервере API без интернета.
