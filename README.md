# haijack

ИИ-ассистент для работы с кодовой базой. Внутри четыре агента — Architect, Coder, Reviewer, Executor, — которые планируют изменение, пишут код, проверяют его по diff и запускают тесты.

Работает на **Windows** (PowerShell, cmd, Windows Terminal), **Android** (Termux или отдельное приложение), Linux и macOS. Зависимостей нет: нужен только Node.js ≥ 18.17, а в готовых сборках для Windows и Android он уже внутри.

## Готовые сборки

| Платформа | Что скачать | Ветка с исходниками сборки |
|-----------|-------------|----------------------------|
| Windows | `lcc.exe` — один файл, Node.js не нужен | [`windows`](../../tree/windows) |
| Android | `haijack.apk` — приложение со встроенным Node.js | [`android`](../../tree/android) |

Сборки делает GitHub Actions при каждом изменении ветки. Скачать их можно на странице [Releases](../../releases) или во вкладке [Actions](../../actions) (раздел Artifacts у последнего успешного запуска).

Ветка `main` содержит общее ядро. Ветки `windows` и `android` добавляют к нему только упаковку под свою платформу.

## Установка из исходников

**Windows.** Поставьте [Node.js LTS](https://nodejs.org) (или `winget install OpenJS.NodeJS.LTS`), откройте новое окно терминала и запустите `setup.bat` из папки программы. Затем в папке своего проекта выполните `lcc`.

**Android (Termux).** Termux ставьте из F-Droid — версия в Google Play устарела.

```bash
pkg update && pkg install -y nodejs-lts git
git clone https://github.com/gkaims666-ship-it/haijack && cd haijack
bash install-termux.sh
```

**Linux / macOS.** `npm install -g . && lcc`

Без установки программа запускается так: `node bin/lcc.js`.

## Ключ API

Ключ ищется в переменных окружения (`ANTHROPIC_API_KEY` или `ANTHROPIC_AUTH_TOKEN`), затем в `.env` в папке проекта, затем в `~/.lcc/.env`. Если его нигде нет, программа спросит ключ при первом запуске и сохранит в `~/.lcc/.env`.

Свой шлюз или прокси, совместимый с Anthropic Messages API, задаётся через `ANTHROPIC_BASE_URL`. Все настройки перечислены в `.env.example`.

## Работа

```
[auto] → добавь в api/users.py эндпоинт удаления пользователя и тесты к нему
```

| Режим | Что происходит |
|-------|----------------|
| `auto` | Architect изучает проект и составляет план → Coder пишет код → Reviewer проверяет diff → Executor запускает тесты. Замечания и упавшие проверки возвращают задачу к Coder, после чего код снова идёт на ревью |
| `plan` | То же, но сначала показывается план и спрашивается подтверждение |
| `solo` | Один агент со всеми инструментами и памятью диалога. Быстрее и дешевле, подходит для вопросов и мелких правок |

| Команда | Действие |
|---------|----------|
| `/mode auto\|plan\|solo` | сменить режим |
| `/yes` | включить или выключить автоподтверждение записи и команд |
| `/model <имя>` | сменить модель для всех агентов |
| `/diff` | показать изменения последней задачи |
| `/undo` | откатить изменения последней задачи |
| `/cd <папка>` | сменить папку проекта |
| `/loop <задача>` | непрерывная задача до остановки |
| `/self <задача>` | улучшить само приложение |
| `/memory`, `/forget`, `/journal` | долговременная память и журнал задач |
| `/clear`, `/cost`, `/status`, `/help` | очистка диалога, расход токенов, настройки, справка |
| `!<команда>` | выполнить команду в оболочке напрямую |
| `/exit`, Ctrl+D, Ctrl+C дважды | выход |

Ctrl+C во время работы прерывает текущую задачу вместе с запущенными процессами.

Однократный запуск: `lcc -p "найди и исправь падающий тест"`, с `-y` — без подтверждений, с `-m solo` — одним агентом.

### Окно приложения

`lcc --app` открывает интерфейс в отдельном окне — без вкладок и адресной строки. Окно рисует движок, который уже есть в системе: Edge на Windows, Chrome или Chromium на других системах; у окна свой профиль, с обычным браузером оно не смешивается. Закрытие окна завершает программу через несколько секунд (если задача ещё идёт — после её окончания), повторный запуск открывает ещё одно окно к уже работающей. В сборке для Windows так запускается `haijack.exe`. Если подходящего браузера нет, интерфейс откроется во вкладке браузера по умолчанию; завершить программу тогда можно кнопкой в настройках.

### Интерфейс в браузере

`lcc --web` запускает тот же ассистент с интерфейсом в браузере: открывает его в браузере по умолчанию и печатает ссылку вида `http://127.0.0.1:<порт>/?t=<ключ>`. Android-приложение использует этот же интерфейс. Сервер слушает только локальный адрес и требует ключ из ссылки в каждом запросе.

### Подтверждения

- Запись файлов, команды и загрузка страниц из сети показывают diff или команду и ждут ответа: разрешить, отклонить или разрешать этот инструмент до конца сессии.
- Опасные команды (`rm -rf /`, `format C:`, `git push --force`, `shutdown` и подобные) требуют ручного подтверждения всегда, даже при автоподтверждении.
- Запись вне папки проекта запрещена, пока не задано `LCC_ALLOW_OUTSIDE=1`.

### Инструкции проекта

Положите в корень проекта `LCC.md` (подойдёт и `CLAUDE.md` или `AGENTS.md`) со стеком, командами тестов и правилами. Этот файл получают все агенты, и он важнее общих стандартов. Пример — `LCC.example.md`.

## Первый запуск и проверка

- Если на компьютере уже работает сервер моделей (Ollama) с моделями, экран входа находит его сам и предлагает войти без ключа. Если сервер запустить позже, список моделей появится без перезагрузки окна.
- Если сервер моделей был выключен или модель ещё докачивалась, программа сама повторяет проверку и подхватывает модель, когда она появится. Перезапускать ничего не нужно.
- Команда `/doctor` (в настройках — кнопка «Проверить, всё ли готово к работе») одним списком показывает, что готово, а что нет, и для каждой проблемы пишет, что сделать: модель, сервер, папка проекта, git, серверы инструментов, токен GitHub.

## Чат

- **Чаты.** Кнопка слева в шапке открывает список: у каждого чата своя история, она сохраняется между запусками. Чаты можно переименовывать и искать по названию. Долговременная память общая.
- **Размышления по ходу.** Если модель сначала рассуждает, рассуждения видны сразу в сворачиваемом блоке — работа не выглядит зависшей.
- **Под каждой репликой** — число токенов, скорость (ток/с) и через сколько начался ответ. Внизу — насколько занят контекст локальной модели.
- **Действия с репликой:** копировать, изменить, повторить. `/retry` выполняет последнюю задачу заново.
- **Очередь.** Написанное во время работы агентов отправится само, когда задача закончится. `Esc` останавливает работу.
- **Ввод:** подсказка команд по `/`, стрелка вверх возвращает прошлые запросы, файлы можно перетащить в окно или вставить из буфера; длинная вставка становится вложением.
- **Изображения.** Снимок экрана, макет или фото ошибки можно приложить кнопкой, перетащить или вставить из буфера — их видят Architect, Coder и ассистент. Нужна модель со зрением; модели без него программа отправит только текст и скажет об этом.
- **План работы.** В задачах из нескольких шагов Coder и ассистент записывают план и отмечают шаги по ходу — в чате это список с галочками.
- **Файлы по «@».** Наберите `@` и часть имени — появится список файлов проекта; в сообщение вставится путь, и агент прочитает файл сам.
- **Уведомление о завершении.** Включается в настройках: системное уведомление, когда задача закончилась, а окно свёрнуто.
- **Разметка:** таблицы, код с подсветкой, кнопки «Копировать» и «Сохранить» у блоков кода; диалог целиком сохраняется в файл Markdown.
- **Свои инструкции, температура, размышления** — в настройках.

### Быстрый старт ответа у локальной модели

Всё работает без интернета: сеть нужна только каталогу моделей. Чтобы большая модель начинала отвечать сразу:

1. При запуске и при смене модели программа загружает её в память заранее (с тем же размером контекста, что и в работе) и держит там час после последнего запроса (`LCC_LOCAL_KEEP_ALIVE`).
2. Пока вы читаете ответ или печатаете, модель заранее читает инструкции и описания инструментов агента, который ответит первым. Настоящий запрос начинается с тех же слов, и сервер не перечитывает их.
3. Общая часть инструкций у всех агентов одинакова и идёт первой, поэтому смена агента в конвейере обходится дешевле.
4. Размышления локальной модели по умолчанию выключены — ответ начинается без паузы на рассуждение. Включить можно в настройках: на сложных задачах результат с ними лучше.

Скорость самой генерации зависит только от компьютера: если модель не помещается в видеопамять, программа скажет об этом прямо.

### Выбор модели

Имя модели и её состояние (загружается, в памяти, ошибка) видны в панели ввода. По нажатию — список установленных моделей с размером; выбранная сразу загружается, прежняя выгружается. Если установлена одна модель, все агенты работают с ней, даже если в настройках указаны другие.

## Связь с другими средами

**Серверы инструментов (MCP).** Тот же стандарт, что в Claude Code, Cursor и других средах. В настройках, раздел «Связи с другими средами», вставьте описание серверов в общем формате:

```json
{ "mcpServers": { "имя": { "command": "npx", "args": ["-y", "пакет-сервера"] }, "по-сети": { "url": "https://example.com/mcp" } } }
```

Оно хранится в `~/.lcc/mcp.json`. Серверы, описанные в файлах проекта (`.mcp.json`, `.cursor/mcp.json`), программа находит сама, но запускает только после вашего разрешения: это команды на вашем компьютере. Инструменты серверов получают агенты; действия, которые что-то меняют, спрашивают подтверждение.

**haijack внутри других сред.** Команда `haijack mcp` (в сборке для Windows — `haijack-cli.exe mcp`) делает программу сервером MCP с двумя инструментами: `haijack_run` — поручить задачу конвейеру агентов, `haijack_ask` — задать вопрос о проекте. Подключение:

```bash
claude mcp add haijack -- haijack mcp        # Claude Code
```

```json
{ "mcpServers": { "haijack": { "command": "haijack", "args": ["mcp"] } } }
```

Второй вариант — для `.cursor/mcp.json` в Cursor и для любого другого клиента MCP.

**haijack как «модель».** Команда `haijack serve` (в сборке для Windows — `haijack-cli.exe serve`) открывает OpenAI-совместимый адрес и печатает его вместе с ключом:

```
Адрес (base URL): http://127.0.0.1:8765/v1
Ключ (API key):   hj-…
```

Их вводят в любой программе, умеющей работать с OpenAI API (Continue, Cline, Open WebUI, свои скрипты). Моделей две: `haijack` выполняет задачу в папке проекта и меняет файлы, `haijack-ask` отвечает на вопросы, ничего не меняя. Ответ идёт потоком: видно, какой агент работает и что он делает. Папка проекта — та, из которой запущена команда (или `--cwd`). Адрес доступен только с этого компьютера. Cursor обращается к моделям со своих серверов, поэтому к адресу на вашем компьютере не подключится — для него есть режим сервера MCP выше.

**Открыть проект в редакторе.** Команда `/open` открывает папку проекта в Cursor или VS Code (`/open cursor`, `/open code`, `/open windsurf`, `/open zed`).

**Правила проекта.** Читаются файлы правил разных сред: `LCC.md`, `CLAUDE.md`, `AGENTS.md`, `.cursorrules`, `.cursor/rules/*`, `.github/copilot-instructions.md`, `.windsurfrules`, `GEMINI.md`. Проект, настроенный под одну из них, работает и здесь.

**Коммиты.** Команда `/commit` (или кнопка «Коммит» в итоге задачи) добавляет все изменения и делает коммит; сообщение по самим изменениям пишет модель, своё можно задать так: `/commit текст`. Файлы, похожие на секреты (`.env`, ключи), в коммит не попадают. Текущая ветка видна в шапке окна рядом с папкой проекта.

**Файлы ветки.** Нажмите на папку проекта и ветку в шапке (или команда `/files`) — откроется список файлов, изменённых в ветке, с окантовкой по состоянию:

- зелёная — готов: файл меняли агенты, ревью и проверка пройдены, недоделок в тексте нет;
- красная — не готов: синтаксическая ошибка, не пройдены ревью или проверка, либо в файле остались пометки недоделанного (`TODO`, `FIXME`, «не реализовано», заглушки);
- жёлтая — под вопросом: изменён одним агентом без ревью, изменён после проверки или изменён вручную.

Под каждым файлом написана причина. Нажатие на файл вставляет его в сообщение. Раскрасить файлы на самом сайте GitHub программа не может — подсветка работает в приложении.

**GitHub.** Обычные операции git агенты выполняют командами. Для задач, запросов на слияние, комментариев и проверок есть инструменты `github_read` и `github_write` (REST API). Токен — в настройках или в переменной `GITHUB_TOKEN`; чтение открытых репозиториев работает и без него. Любое изменение на GitHub спрашивает подтверждение. Другие сервисы (GitLab, Jira, базы данных и прочее) подключаются через их серверы MCP.

## Работа до полного выполнения

В режимах `auto` и `plan` задача считается выполненной, только когда у Reviewer нет замечаний, проверки Executor проходят, а при самоулучшении пройдена ещё и самопроверка. Если после захода что-то осталось, программа начинает новый заход: Architect получает список оставшихся проблем и планирует, как их закрыть.

Заходов по умолчанию не больше пяти (`LCC_MAX_CYCLES`, 0 — без ограничения). Ограничение стоит потому, что ни одна модель не гарантирует результат: задача, которая не сходится, иначе расходовала бы ресурсы бесконечно.

`/loop <задача>` (в браузере — кнопка «Непрерывно») запускает непрерывную задачу: итерация за итерацией, пока вы её не остановите. Каждая итерация знает, что сделано в предыдущих. Результаты пишутся в `~/.lcc/logs/loop-<время>.md`. Цикл бесконечный: останавливаете его только вы (кнопка «Стоп», Esc или Ctrl+C). Если несколько итераций подряд не удались (сервер модели недоступен, нет сети), цикл не прерывается, а делает паузу — от 5 секунд до 5 минут — и пробует снова. Если несколько итераций подряд ничего не изменили, модель получает указание искать глубже: непроверенные крайние случаи, тесты, производительность, документация.

## Память и журнал

После каждой задачи программа одним запросом к модели обновляет долговременную память — `~/.lcc/memory.md`: устройство проектов, ваши требования, найденные подводные камни. Память попадает в инструкции всех агентов и не стирается ни при перезапуске, ни при очистке диалога: `/clear` сначала переносит суть разговора в память и только потом очищает диалог. `/memory` показывает память, `/forget` стирает, `/journal` показывает последние задачи. Отключить память: `LCC_MEMORY=0`.

Диалог тоже сохраняется на диск: и то, что показано на экране в браузере, и разговор с ассистентом в режиме `solo` — после перезапуска он продолжается с того же места. Очистка диалога стирает оба.

## Самоулучшение без переустановки

`/self <задача>` (в браузере — кнопка «Приложение») направляет задачу на код самого приложения:

1. Создаётся копия кода в `~/.lcc/app/next`. Работающая версия не затрагивается.
2. Агенты меняют копию по обычному конвейеру: план, код, ревью по diff.
3. Самопроверка в отдельном потоке: каждый модуль загружается, веб-сервер поднимается и требует ключ, скрипт страницы синтаксически корректен. Там, где есть отдельный `node`, дополнительно запускаются тесты приложения. Сбой возвращает задачу к Coder.
4. Копия становится версией `~/.lcc/app/v<N>`, и программа перезапускается в том же процессе — без переустановки, одинаково в exe, apk и при запуске из исходников.

Переключаться вручную не обязательно: если обычная задача похожа на просьбу улучшить само приложение («в этом приложении добавь…»), программа сама спросит, выполнить ли её над кодом приложения.

Если новая версия дважды не смогла запуститься, загрузчик сам возвращает предыдущую. `/self status` показывает работающую версию, `/self undo` откатывает последнюю доработку, `/self reset` возвращает заводскую версию. Загрузчик `bin/lcc.js` всегда берётся из заводской версии, поэтому сломать его доработкой нельзя. При установке новой версии приложения (новый exe или apk) доработки старой версии отключаются, их код остаётся на диске.

## Локальные модели

Программа работает с любым сервером с OpenAI-совместимым API: Ollama, LM Studio, llama.cpp. Настроить можно на экране входа в браузере или в `.env`:

```
LLM_PROVIDER=local
LOCAL_LLM_BASE_URL=http://127.0.0.1:11434/v1
LOCAL_LLM_MODEL=<основная модель>
LOCAL_LLM_FAST_MODEL=<быстрая модель для Executor>
LOCAL_LLM_FALLBACK_MODEL=<запасная модель>
LOCAL_LLM_NUM_CTX=16384
LOCAL_LLM_TIMEOUT=180000
```

`scripts/setup_local_llm.sh --model <имя>` (Windows: `scripts\setup_local_llm.ps1`) проверяет Ollama, запускает сервер и скачивает модель. Нужна модель с поддержкой вызова инструментов.

**Поиск и скачивание модели в приложении.** На экране входа и в настройках есть кнопка «Найти и скачать модель». Она открывает каталог Hugging Face: поиск по всем общедоступным моделям в формате GGUF, страницами, сначала самые скачиваемые. Выбираете модель, затем вариант сжатия (с размером файла) — приложение скачивает его через Ollama и показывает ход загрузки; загрузку можно остановить и позже продолжить. Там же можно скачать модель из библиотеки Ollama по имени. В терминале то же делает `/pull <имя>`, например `/pull hf.co/автор/репозиторий:Q4_K_M`.

Скачивание работает только с Ollama: веса хранятся на её сервере. Каталогу нужен интернет. Не каждая модель из каталога умеет вызывать инструменты, а без этого агенты не могут работать с файлами: смотрите описание модели.

Что программа делает, чтобы локальная модель работала:

- **С Ollama говорит на её собственном API.** Только так можно задать размер контекста: через OpenAI-совместимый адрес Ollama этот параметр игнорирует и выбирает контекст сама — слишком маленький или слишком большой для памяти компьютера. Размер задаётся в настройках («Размер контекста») или `LOCAL_LLM_NUM_CTX`, по умолчанию 16384.
- **Даёт короткие инструкции.** Локальная модель читает запрос целиком на каждом шаге, поэтому правила для агентов изложены для неё в несколько раз короче.
- **Работает с моделями без встроенного вызова инструментов.** Если модель его не поддерживает (так бывает у сборок с Hugging Face), программа переходит на текстовый режим: описывает инструменты в инструкции и разбирает вызовы из текста ответа. Он менее надёжен, но работает с любой моделью.
- **Вырезает размышления** (`<think>`) из ответа и упрощает схемы инструментов до понятных llama.cpp.
- **Ждёт медленную модель и объясняет задержку.** Первый ответ ожидается до 15 минут (`LOCAL_LLM_FIRST_TIMEOUT`): модель загружается в память и читает запрос. Если модель не помещается в видеопамять и считает на процессоре, программа прямо говорит об этом и советует вариант поменьше.
- **Переходит на запасную модель** при обрыве связи, таймауте или нехватке памяти.
- **Проверяет сервер перед работой**: запущен ли он и скачана ли модель.

Локальные модели пишут код заметно хуже моделей через API и чаще ошибаются в вызовах инструментов; на телефоне большую модель запустить нельзя, поэтому приложение на Android обращается к серверу моделей на компьютере.

## Один диалог на компьютере и телефоне

На компьютере запустите `lcc --web`, откройте «Настройки» и включите «Открыть доступ в локальной сети». Программа покажет ссылку. В Android-приложении выберите на экране входа «Компьютер» и вставьте её: телефон покажет тот же диалог, а работа будет идти на компьютере. Ссылка содержит ключ доступа и передаётся без шифрования, поэтому включайте доступ только в сети, которой доверяете.

## От чего зависит качество кода

Главный фактор — модель. Программа не может сделать слабую модель сильной, поэтому для лучшего результата задайте самую сильную модель, доступную вашему ключу:

```
LCC_MODEL_ARCHITECT=claude-opus-5-5
LCC_MODEL_CODER=claude-opus-5-5
LCC_MODEL_REVIEWER=claude-opus-5-5
LCC_EFFORT=high
```

Остальное — рабочий процесс, который закрывает типичные ошибки моделей:

| Механизм | Какую ошибку закрывает |
|----------|------------------------|
| Файл нельзя изменить, пока агент его не прочитал, и если он изменился после чтения | правки по памяти и по догадке |
| Синтаксическая проверка сразу после записи (JS, JSON, Python) | ошибка обнаруживается через несколько шагов, а не сразу |
| Reviewer получает настоящий diff всех изменений, а отчёт Coder считает заявлением | ревью «на слово» |
| Любая правка после ревью снова идёт на ревью | непроверенные исправления в итоге |
| Executor проверяет изменённое поведение запуском, а не только существующими тестами | «тесты зелёные», но новое не проверялось |
| Инженерные стандарты в промтах: минимальное изменение, стиль проекта, исправление причины, тесты, запрет заглушек | раздутые правки, чужой стиль, TODO вместо логики |
| `fetch_url` для сверки с документацией | выдуманные сигнатуры API |
| Рассуждения модели включены (`LCC_THINKING=adaptive`) | поспешные решения в сложных местах |
| Кэширование промта | длинные задачи дешевле и быстрее, можно дольше исследовать код |

Если API не принимает рассуждения, `effort` или кэширование (старая модель, сторонний шлюз), программа отключает отвергнутую возможность до конца сессии и продолжает работу.

## Устройство

```
bin/lcc.js               загрузчик: выбор версии кода, откат при сбое, перезапуск
LCC.md                   устройство и правила для агентов, работающих над самим приложением
src/
  index.js               аргументы CLI, выбор режима запуска
  session.js             команды и запуск задач — общие для терминала и браузера
  memory.js              долговременная память и журнал
  self/                  версии кода, копия для доработки, самопроверка
  config.js              .env, окружение, сохранение ключа
  platform.js            определение ОС и выбор оболочки
  api/anthropic.js       потоковый клиент Messages API: SSE, инструменты, повторы, кэш, рассуждения
  api/openai.js          локальные модели: OpenAI-совместимый API и адаптер вызовов инструментов
  agents/
    prompts.js           роли и инженерные стандарты
    agent.js             цикл «модель → инструменты → модель», сжатие контекста
    orchestrator.js      конвейер с циклом ревью и проверки
  tools/
    files.js             read_file, write_file, edit_file, list_dir
    search.js            glob, grep на чистом JS
    command.js           run_command: PowerShell, cmd или bash; завершение дерева процессов
    web.js               fetch_url
    changes.js, diff.js  снимки файлов, unified diff, откат
    checks.js            синтаксическая проверка после записи
  ui/                    терминал: цвета, вывод агентов, REPL
  web/                   сервер, страница и рендерер для браузера и Android
test/                    модульные тесты, тесты на мок-сервере API, e2e.mjs
```

Права агентов: Architect и Reviewer только читают и ищут; Executor читает и выполняет команды; Coder может всё. `fetch_url` доступен Architect, Coder и Reviewer и всегда спрашивает подтверждение.

Оболочка для команд: на Windows — `pwsh`, если установлен, иначе `powershell.exe` (команда передаётся через `-EncodedCommand`, поэтому кавычки и кириллица не ломаются); в Termux — `bash`; в Android-приложении — системная `sh`; на Linux и macOS — `bash` или `sh`. Переопределяется через `LCC_SHELL`.

## Тесты

```bash
npm test                               # модульные тесты и тесты на мок-сервере API
node test/e2e.mjs node bin/lcc.js      # запуск программы целиком на мок-сервере
```

Тесты не обращаются в интернет и не трогают настоящий `~/.lcc`. GitHub Actions запускает их на Ubuntu и Windows с Node 18 и 22.
